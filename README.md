# Data analysis work: прогнозирование оттока клиентов телеком-компании

Курсовая работа «Комплексный анализ данных и моделирование».
Задача: бинарная классификация, предсказать, уйдёт ли клиент (`Churn Value`: 1 уйдёт, 0 останется).

## Данные

- **Датасет:** [Telco Customer Churn](https://www.kaggle.com/datasets/yeanzc/telco-customer-churn-ibm-dataset), файл `Telco_customer_churn.xlsx`.
- **Размер:** 7043 клиента, 33 исходных признака.
- **Целевая переменная:** `Churn Value`.
- **Исключены как утечка целевой переменной:** `Churn Label`, `Churn Score`, `CLTV`, `Churn Reason` (известны только постфактум).

Исходный файл в репозиторий не коммитится. Положите его в `data/raw/`.

## Как запустить

1. Установить зависимости из `pyproject.toml`.
2. Положить `Telco_customer_churn.xlsx` в `data/raw/`.
3. Из корня репозитория выполнить:

```bash
python scripts/prepare_data.py
```

Чтобы не открывались окна с графиками, задайте переменную окружения `MPLBACKEND=Agg`.

Шаги выполняются по порядку: `data` → `preprocessing` → `features` → `data_dictionary`.
Модули в `src/main_project/` являются скриптами (код выполняется на верхнем уровне),
поэтому запускайте их через `scripts/prepare_data.py`, а не импортируйте.

## Принятые решения по данным

- `Total Charges` приведён к числу; пустые значения у клиентов с `Tenure Months = 0` заполнены нулём (счетов ещё не было).
- Значения «No internet service» и «No phone service» объединены с «No».
- `Contract` закодирован порядково (0, 1, 2), номинальные признаки закодированы one-hot с `drop_first`.
- Служебные и неинформативные колонки (`CustomerID`, `Count`, `Country`, `State`, `City`, `Zip Code`, `Lat Long`) исключены.
- Мультиколлинеарные признаки убраны итеративно по порогу VIF > 10. Полный датасет сохранён отдельно, чтобы древесные модели не теряли информацию.
